# Stress Test

A reasoning artifact compressed from a conversation testing whether LoopThing has a real wedge or is a feature inside a bigger platform's roadmap.

## Intent

The goal was to stress-test whether LoopThing has a defensible wedge, identify whether the value is real or theatrical, and decide what to commit to before building further. The conversation narrowed the idea rather than defending the original concept.

## Problem

People accumulate large corpuses of AI conversations where modern reasoning increasingly happens. The chats are thrown away, and the artifacts they produce do not preserve the moves that produced them. People copy-paste old chats into new chats because they suspect value is in there but cannot locate it: "They grab everything. That's the problem. I don't know where my gold is."

## Critical Messages

- "It's value is truly to the creator" — narrowed the audience from recipients, creators, and RL to creator leverage.
- "Copy and pasting some chats into new chats" — surfaced the manual behavior LoopThing can displace.
- "They grab everything. That's the problem. I don't know where my gold is." — crystallized the job-to-be-done as find the gold.
- "Worth swinging for the fences. Semantic decision layer is awesome" — committed the strategy to category creation rather than a small feature.

## Framing Diffs

| From | To | Why it mattered |
| --- | --- | --- |
| Serves recipients, creators, and RL | Creator leverage is the spine | Made the product buildable. |
| Store the thinking | Compress the thinking | Compression quality became the product. |
| Format and viewer | Semantic decision layer over git | Stopped fighting GitHub on code-history turf. |
| Retrieval tool | Handoff substrate | Gave the wedge a falsifiable test. |
| Memory feature | Category creation | Moved away from lab-roadmap competition. |

## Discarded Branches

- Show-your-work format for recipients: rejected because recipients mostly read conclusions, not working-out.
- Journaling tool for creators: rejected because the value is real but too habit-shaped and small.
- RL training data play: rejected as primary wedge because the buyer set is tiny and labs have richer signal.
- CLI as only user surface: acceptable for v1, but wrong long-term for non-developer handoff.
- Viewer, format spec, or SaaS before compression: rejected as premature infrastructure.
- Pitching as memory-but-better: rejected because labs will ship much of that for free.

## What Survives Criticism

There is a missing primitive: a compressed reasoning artifact. The most valuable initial use case is handoff between people working with AI tools.

This survived because it has a falsifiable test: can someone who was not in the conversation end up where the creator is, fast, without reading the transcript?

## Where This Might Be Wrong

- Compression quality might not be reachable. If the artifact misses the gold, it is worse than the transcript.
- Handoff might be too rare a transaction to support a company.
- Labs might build cross-tool handoff faster than expected.
- The semantic decision layer might be right but too early.

## Outcome

Committed to:

- Handoff as the spine
- Compression-first
- Semantic decision layer over git
- Open-source CLI as v1 developer wedge
- Category creation as the strategic bet

Not committed to:

- The name LoopThing
- A viewer, format spec, or multi-tenant SaaS
- A specific wedge persona
- Retrieval as the v1 use case
- Whether this is venture-shaped or open-source-shaped

## Next Action

Run the compression test: 20 chats, three variants per chat, mixed contexts. This gates everything else.
